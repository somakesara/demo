## STAGE DEFINITION
A stage is any one of:
- a TEMP TABLE creation
- a CTE in a WITH clause
- a nested subquery level (do NOT collapse levels — each is its own stage)
- a major INSERT / UPDATE / DELETE
- a control-flow branch whose outcome is a materially different result set
- the final RETURN

Stages are presented in **logical reading order** — the order that helps a human read the code top-to-bottom. This is not the planner's execution order (CTEs may be inlined, reordered, or never executed; that's the planner's business, not the reader's).

## PER STAGE, THE HTML MUST RENDER
1. Badge: TEMP TABLE / CTE / SUBQUERY / WRITE / BRANCH / RETURN, with stage number
2. Title + source alias suffix (e.g. "Lines priced · source alias: t2")
3. 2–3 sentence explanation of WHY this stage exists. Not a SQL re-read. If the code is ugly here, say so plainly.
4. **Alias decoder** — grid of `cryptic → real meaning` for every alias used in this stage. Mandatory.
5. **Tables panel** — chips per table/source. Solid dark = inner join, dashed = left join, normal = derived from prior stage. Source alias on every chip.
6. **Inputs → Outputs** cards with arrow between them.
7. **SQL fragment** — preserve every identifier from the source character-for-character. Highlighting is presentation only: wrap tokens in spans for color, never rename, reformat aggressively, or paraphrase. Cryptic aliases highlighted in accent color so they jump out.
8. **Quirk callouts** — if the stage has dead code, suspicious LEFT-where-INNER-was-meant, dry-run gotchas, unused selected columns, or a window function whose result depends on row ordering not specified by an ORDER BY: add a small amber callout. Do not silently fix. Do not rewrite the source.

## STICKY BOTTOM — ROW INSPECTOR (mandatory)

- Each chip: source alias in accent color above, real column name below, value at bottom
